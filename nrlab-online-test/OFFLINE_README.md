# NRLAB CLOUD — Гибридный режим (тестовая версия)

## Запуск и установка

1. Пока есть интернет, откройте [NRLAB CLOUD](https://alimahmuddov-beep.github.io/onedent-calculator/nrlab-online-test/).
2. Войдите в **одобренную** учётную запись врача или администратора, дождитесь загрузки справочников и затем перезагрузите страницу один раз при наличии интернета.
3. В Edge/Chrome установите сайт как приложение через меню браузера (если доступна команда «Установить приложение» / «Приложения»). Программа продолжит работать через тот же профиль браузера.
4. После установки отключите интернет и откройте приложение вновь: вместо облачной авторизации откроется автономная форма `offline.html`. При первом использовании без интернета форма не работает: сначала требуется онлайн-вход.
5. Укажите код пациента (в тестах не используйте реальных пациентов), клинику, цвет, дату сдачи и работы по зубной формуле. Прикрепите верхнюю и нижнюю челюсти, скан-маркер и дополнительные файлы при необходимости. Нажмите «Сохранить заказ на устройстве».
6. Сохранённый заказ остаётся в IndexedDB этого браузера, даже если приложение закрыто. Статус — **ожидает синхронизации**: лаборатория заказ ещё не получила.
7. Включите интернет, откройте основной облачный кабинет, войдите в *тот же аккаунт*. Программа попытается отправить очередь. Если связь прервалась, зайдите в «Локальная очередь» и нажмите «Отправить в облако». Заказы с ошибками останутся в очереди.
8. Убедитесь, что очередь пуста и заказ появился в облачном разделе «Заказы» прежде, чем считать его доставленным.

## Защита от потери заказов

- Сначала заказ записывается **локально**, затем отправляется в Supabase; если связь пропадёт, запись остаётся на компьютере.
- За каждой отправкой закрепляется постоянный UUID. RPC `place_order_idempotent` защищает от дублирования заказа при повторных попытках.
- Вложения хранятся локально в очереди и по одному загружаются в закрытый бакет; удачно синхронизированные файлы помечаются.
- Перед закрытием вкладки при незаписанной форме или заказах в очереди браузер может показать системное предупреждение. Настраиваемый текст в таком системном окне браузеры не гарантируют; приложение дополнительно показывает постоянное сообщение.
- На телефонах системное событие закрытия может не сработать. **Нельзя гарантировать синхронизацию после закрытия программы**: для завершения отправки откройте приложение с интернетом.
- Если срок сдачи к моменту синхронизации стал недопустимым (менее 6 рабочих дней), заказ останется в очереди для изменения даты. Суббота и воскресенье не считаются.

## Ограничения

- Офлайн работает **создание заказов и просмотр локальной очереди**, но не изменение облачных статусов, администрирование или первичная авторизация.
- Полные данные локально хранятся на устройстве в хранилище браузера, без сквозного шифрования. Для этой версии — только вымышленные данные пациентов и тестовые файлы. Не используйте общедоступный компьютер.
- Очистка данных сайта, сброс профиля браузера или нехватка дискового пространства может уничтожить несинхронизированную очередь.
- Локальная очередь отдельна для каждой учётной записи. До синхронизации она **не видна на других устройствах**.
- Онлайн-приложение требует Supabase. Права врача по-прежнему проверяются сервером при фактической синхронизации.
- Исходный публичный сайт `order/index.html` и отдельные базы прежних версий проекта не изменяются.

## Файлы реализации

- `index.html` — онлайн-кабинет и локальная очередь
- `offline.html` — автономная форма для работы без сети
- `offline-store.js` — IndexedDB (пользовательские справочники, файлы и очередь)
- `sw.js` — Service Worker, который сохраняет офлайн-страницу и открывает её без сети
- `manifest.webmanifest` и `icon.svg` — установка приложения
- `migrations/offline_sync.sql` — серверный обработчик повторных отправок.

**Важно:** уведомление о неотправленных заказах — не подтверждение доставки. Доставку подтверждает только появление заказа в облаке.
